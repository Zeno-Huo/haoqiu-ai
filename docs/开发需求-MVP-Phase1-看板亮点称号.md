# 好球Ai · 数据看板「亮点称号 + 位置维度」改版（V1.2）

> 变更来源：用户验收提出「谁最亮眼谁当主角」，用称号标签 + 按位置区分亮点。视觉用 impeccable 审美规范。

## 一、目标

数据看板从「平均的格子」改为「**谁最亮眼谁当主角**」：
- 每个球员突出「最亮眼的那项数据」放大展示，配称号徽章（如「抢断王」）。
- 不同位置看不同亮点（前锋看进攻、中场看组织、后卫看防守）。

## 二、球员位置

- 建比赛名单时，每个球员选择位置：**前锋 / 中场 / 后卫**（门将暂不做）。
- 名单录入步骤加一个位置下拉。

## 三、位置 → 重点指标

| 位置 | 重点指标（亮点候选） |
| --- | --- |
| 前锋 | 射门、突破 |
| 中场 | 传球、拿球 |
| 后卫 | 拦截、抢断 |

## 四、称号系统（全队评比）

- 射手（射门最多）、突破王（突破成功最多）、传球大师（传球成功最多）、拿球王（拿球最多）、拦截王（拦截最多）、抢断王（抢断最多）。
- 每个球员**最多一个称号**（取他在某指标全队第一时对应的称号；若多项第一，取他最突出的一项）。
- 称号徽章：奖章/金色样式，一眼识别。

## 五、引擎改动（engine.ts）

- 按位置生成数据分布：前锋射门/突破事件多，中场传球/拿球多，后卫拦截/抢断多（否则「前锋射门多、后卫抢断多」不合理）。
- 计算全队各指标第一名，为球员生成称号 + 亮点项（highlight）。

## 六、数据模型改动（types.ts）

- Player 增加 `position: '前锋' | '中场' | '后卫'`（必填）。
- PlayerAnalysis 增加 `title?: string`（称号，无称号可为空）、`highlight?: { key: string; label: string; value: number }`（要放大的亮点项）。

## 七、视觉（impeccable 审美规范）

**务必先读** `~/.workbuddy/skills/impeccable/SKILL.md` 及 `references/` 下相关文件（arrange/typeset/color/bolder）。

- 美学方向：**记分牌 + 勋章风**，大胆的排版层级，有力量感与荣誉感。
- 亮点数据用「记分牌大数字」突出（如「抢断 5」）；称号像「勋章」徽章。
- 辅助数据缩成一行小字；综合评分 1-10 保留但弱化为次要。
- 避免：卡片套卡片、纯黑 #000/纯白 #fff、泛 AI 配色（青+深色、紫蓝渐变）、无意义圆角+阴影。
- 保留「演示数据」说明条与「分析点评」。
- 移动端优先，响应式。

## 八、逻辑测试（diagnose 方法论）

改完后用「重现 → 假设 → 验证 → 修复 → 回归」验证看板逻辑：
- 称号判定正确（全队某指标第一）；并列第一的处理；
- 亮点项选择正确（位置重点指标里该球员最突出者）；
- 数据全 0 / 极值 / 单个球员等边界情况不报错；
- 评分 1-10 推导正确。

## 九、验收

- 名单可录位置；看板突出每个球员亮点 + 称号徽章；视觉主次分明有审美；`npm run build` 通过。
