# 好球Ai 产品开发全记录

**周期**：2026-08-22 → 2026-09-14（25 天）
**产品**：AI 足球比赛表现分析 —— 用户上传比赛视频，AI 输出战术亮点/不足、球员点评、1-10 评分看板
**状态**：已上线，真实付费调用跑通，团队模式与个人比赛模式均可用

## 导读：这 25 天到底走了什么路

一句话概括：**从「本地伪随机模拟」走到「真实 AI 视频分析」，中间砍掉了一整套 GPU 方案、试了 6 版提示词、踩了两个成本坑、纠正了三次认知偏差。**

三次架构大转向：
1. **8/25**：放弃自建 GPU 检测（YOLO），改接大模型视频理解 API
2. **8/29-8/30**：VLM 与 YOLO 反复拉扯三次，最终彻底砍掉 YOLO
3. **9/13**：推翻「靠精确计数」的产品逻辑，改为定性描述 —— 这一转向让质量产生质变

## 阶段一 · 起点：一台没有显卡的电脑（8/22 - 8/23）

### 关键节点

- **8/22 立项**，技术栈定为 Vite + React + TS + Tailwind（静态可部署），数据存 localStorage。
- 硬件现实：Intel i5-8259U / 8GB 内存 / 无 GPU → **本地跑模型不可行，必须走云端**。
- 第一版「AI 分析」其实是 `engine.ts` 里 343 行的**本地伪随机引擎**。
- **产品侧面就立了规矩**：明确告知用户这是模拟数据，并在报告页挂黄色说明条。

### 遇到的难题

**① 上传视频步骤卡死**
「下一步」按钮 `disabled={!video}`，用户明明有视频却过不去。
- 第一版误判为"没有视频文件"，加了「暂不上传，使用示例视频」跳过入口。
- **真实原因**：卡在**时长读取**——`readVideoDuration` 没有超时，元数据不返回就永久卡住。
- 修法：选中文件即刻放行，时长读取改为后台尽力而为（3 秒超时）。

**② 模拟事件的时间超出视频真实时长**
22 秒的视频，报告里出现 1 分多钟的"精彩瞬间"。
- 根因：事件时间用了 `rng.int(60, max(120, duration-30))`，短视频时**下限 60 高于上限**，时间全落在 60–120 秒。
- 修法：改为 `rng.int(0, max(duration-1, 10))`。

**③ 用户质疑「模拟却假装分析」**
- 用户提出两点：模拟引擎根本用不到视频却卡上传；分析页 25% 是假阶段进度而非真实总进度。
- 处理：删掉整个上传步骤，分析页改为极简 loading，**不再假装**。
- **沉淀的原则**：模拟阶段产品要诚实简洁，不"假装"做真实分析。

### 关键发现

- 沙箱的 safe-delete 防护会拦截批量删除（阈值 50 个文件）→ 被迫在 `vite.config.ts` 设 `build.emptyOutDir: false`。**这个设置埋下了「dist 无限堆历史 bundle」的长线隐患**（后来真出过事故）。

## 阶段二 · 第一次大转向：砍掉 GPU（8/25 - 8/27）

### 关键节点

- **8/25 用户拍板**：不再需要 HAI/GPU，改为接入大模型视频理解 API（千问 / GLM-4V）。
- 理由：HAI GPU 是用户自己的实例，**我够不着**（沙箱到 HAI 公网不通、`~/.ssh` 不可写），排障只能"我出指令、用户人肉执行"；且自建检测维护成本高。
- 转向后整套重新变纯 CloudBase，我可以完全接手。
- 双链路设计：「即时分析」（VLM）+「深度复盘」（GPU），后深度复盘被砍。

### 遇到的难题

**① 登录卡点**：网关路由 `EnableAuth=false` → 网关注入 userId 失败 → 后端抛 `AUTH_REQUIRED`。

**② 「无法连接 CloudBase 服务」—— 排查了半天的诡异 400**
每次请求都返回 400/145，连 `/health` 都崩。不是网络、不是 callFunction、不是函数类型。
- **真因 = 模块加载期崩溃**：`cloudbaserc.json` 里 `ALLOWED_WEB_ORIGINS` 用**分号**分隔，而 `http-cors.ts` 按**逗号** split → 整串被当成一个非法 URL → `loadConfig()` 抛异常 → 函数每次调用在模块加载阶段就崩。
- 修法三处：改回逗号分隔 + split 改正则 `split(/[,;]/)` 防复发 + 重新编译部署。

**③ 存储不一致**：`haoqiu-vlm` 还在用文档型数据库读写任务，而体验版**根本没有文档库** → 即便填了 key 也会崩 `RESOURCE_NOT_FOUND`。
- 修法：重写为用 `cos-nodejs-sdk-v5` 直接读写 `db/task/<id>.json`。

### 关键发现

**HAI 的能力上限被摸清了**：worker 只输出「类别 → 被检测到的帧数」，逐帧检测框仅用于画标注视频、**不落盘**。也就是说——
> **没有球员 ID、没有逐帧坐标、没有传球/射门/控球/比分。**

个人统计需要球员追踪 + 事件识别，是另一个量级的工作。这为后来砍掉它埋下伏笔。

## 阶段三 · VLM 六轮死磕（8/28）—— 全程最曲折的一天

这是整个项目**最密集的模型调优日**，一天内换了 6 个方案。

### 六个版本

| 版本 | 方案 | 结果 |
|---|---|---|
| 1 | 换 `qwen-vl-max` + 重写 prompt（~150 行） | 输出全是废话，数字全空 |
| 2 | 精简 prompt 到 ~52 行（减 65%）、全改正面指令 | 用户实测「完全失真，射门都不是射门」 |
| 3 | 折中抽帧（每 `max(2s, dur/16)` 一帧、cap 16 帧） | 4 分钟视频每 15 秒 1 帧，**射门<1 秒完全抓不到** |
| 4 | 5 轮 VLM，每轮传完整视频 + 针对性 prompt | 会说"第 23 分钟"、没进球编 2:1 —— **会编造叙事** |
| 5 | 密集抽帧 480 帧 + 分批逐帧裁判 | 云函数报错 `res.body.pipe is not a function` |
| 6 | **回退多轮整视频直传** | 成为后续稳定架构 |

### 难题与解法

**① 提示词为什么越写越差**
根因三条：
- prompt 太长（~150 行），模型注意力被规则分散
- JSON 模板全是 `null`，等于在教模型"默认答案就是空"
- 负面约束过多（"禁止""不要""绝不"出现十几次），模型被训得不敢填任何东西

**② `res.body.pipe is not a function`**
- 根因：Node18 云函数里 `fetch` 返回的 `Response.body` 是 **Web Stream**（ReadableStream），**没有 `.pipe()` 方法**（那是旧的 Node Streams API）。
- 处理：放弃抽帧路线，回退整视频直传。

**③ `ffmpeg-static` 云端 ENOENT**
- 根因：它的二进制是 postinstall 才下载的，云端装依赖时下不到。
- 修法：改用 `@ffmpeg-installer/ffmpeg`（二进制直接打进 npm 包）。

**④ 云函数 `/tmp` 只有 517MB**
- 绝不能把原片下载到磁盘再处理，必须让 ffmpeg **直接读 COS 签名 URL 流式处理**。

### ★ 决定性发现：高机位实测（推翻此前悲观判断）

| 项 | 结论 |
|---|---|
| 球员号码 | ✅ **准**（3/7/14/22/33 全对）|
| 画面记分牌 | ✅ **可读**（比分 4:0、比赛时间都对）|
| 球员位置 | ❌ **会错**（14 号后卫被认成前锋）→ 直接去掉 position 字段 |
| 射门识别 | ⚠️ 会漏判 |

**由此定下贯穿全程的「VLM 能力边界」**：

- **可靠**：球衣号码、文字表现评价、画面记分牌比分/时间
- **部分可靠**：事件标签（射门会漏）
- **会编造**：精确计数、控球率、无记分牌时的比分、球员位置

> 这条边界成了后续所有产品决策的准绳：**看板只展示可靠项。**

### 其他关键发现

- **上传限制重定**：用户上传 500MB 视频被拦，手动压到 16MB（≈0.43Mbps）导致画质崩坏。查证千问硬限制后确认：**画质瓶颈在码率不在分辨率**，16MB 是灾难性的。改为云端自动压缩（目标 ≤120MB / ≤5 分钟）。
- **仓库是 PUBLIC**：`gh api` 查出仓库是公开的（记忆里一直以为是私有）。差点泄露密钥——本地 `cloudbaserc.json` 新增了明文 `VLM_API_KEY`，且该文件**被 git 跟踪**（虽在 .gitignore 里但对已跟踪文件无效）。处理：`git rm --cached` 退出跟踪 + 全历史扫描确认密钥从未进过 git。
- **UI 位置红线**：我以"根治 z-index"为由把「历史复盘」从右上角挪到首页底部，用户强烈反对：「谁让你挪的，放回右上角」。**由此写入协作红线：UI 位置/布局属于用户决策，不能因技术上"更合理"就擅自改。**
- **部署事故**：改完 CSS 后用户仍点不开——排查发现逻辑正确，但**部署用的是改动前的旧 dist**（改 CSS 之前就跑过 build）。**教训：前端改完源码必须重新 build 再部署。**

## 阶段四 · YOLO 与 VLM 的三次拉扯（8/29 - 8/30）

### 三次纠偏（全部由用户质疑触发）

1. **我提议「YOLO 降级为回放」** → 用户质疑「YOLO 不该是主角吗？」→ 撤销，回到 4 层能力地图。
2. **我提议「VLM 先认人再指挥 YOLO」** → 用户质疑「之前只接 YOLO 也能出复盘，不用这么复杂吧」（用户记忆正确）→ 撤回。
3. **最终分工**：YOLO = 复盘引擎，VLM = 可选文字润色层。

### 难题

**① HAI worker 上传卡死 10 分钟 + 进程自杀**
- **根因①**：worker 生命周期内只建一个 `httpx.Client`，先用它下载 70MB 视频（长连接），下载完连接已半关闭，再用同一个 client 上传 → **请求既不返回也不超时，永久挂起**。
- 反证很漂亮：诊断脚本每次新建 client，只做上传 → 2KB / 0.9 秒成功。**这解释了为什么"单独测永远正常、真跑必卡"。**
- **根因②**：主循环没有顶层 `try/except`，任何边缘异常冒泡即进程退出 → **GPU 在烧钱，却没人领任务**。

**② 架构根因：网关地址写错**
- envId 直连域名**必须带 `-<appid>` 后缀**（appid=1352817304），少了就 404 `INVALID_ENV`。这个错配之前一直没被确认过。

### 关键发现

- **`cloudbaserc.json` 的拆分坑**：它在 .gitignore 里但仍被 git 跟踪（早前 force-add 过），`git reset --hard` 会清掉密钥 → 每次 reset 前先备份。
- **孤儿视频堆积的三个根因**：① 网页删除是假删除（只删 localStorage）；② queued 任务无 TTL，worker 不在线时 `attempt` 恒为 0 → 任务永远排队；③ 视频从不清理（retention 只是配置项，无执行逻辑）。
- 清出 **25 个孤儿视频 / 4775.2 MB**。

### ★ 8/30 用户拍板：彻底砍掉 YOLO / HAI

决策理由：
- HAI GPU 常驻成本高
- 2382 行 Python 服务维护重
- worker 卡死导致任务永久排队
- **热区/跑位/连线依赖球员坐标，而 VLM 在「球员场上位置」会编造，做出来也是假数据**

执行：先推 GitHub 备份并打 tag `backup-before-vlm-only`，再全量删除 `hai-service/`（19 个 Python 文件 2382 行）。同日用户在 HAI 控制台销毁实例，按小时计费彻底停止。

## 阶段五 · 系统性排障（9/08 - 9/12）

这几天基本在解决"为什么又卡住了"。

### 卡 0% 的终极根因（最值得记的一次排障）

**现象**：传了新视频，比赛分析一直卡 0%。

**根因**：**任务存储路径不一致**。两条代码线混搭埋的雷：
- `haoqiu-api`（rc001 版）把任务写到 `db/rc_task/<id>.json`
- `haoqiu-vlm`（Codex 多轮版）硬编码读 `db/task/<id>.json`

→ 永远读到 null → 返回 `task not found` → 任务永久 queued → 前端卡 0%。

**教训**：排查「卡 0%」先对比「api 写哪、vlm 读哪」两个前缀，再查模型名是否已下线。

### 其他关键问题

| 问题 | 根因 | 解法 |
|---|---|---|
| 报告数据无效 | `qwen-vl-max` / `qwen-vl-plus` 已被阿里云**下线** | 换模型名 |
| 15 分钟时长限制残留 | 只去了大小限制，时长限制**漏改 4 处** | 4 处统一放开 |
| 比赛分析 ENOSPC | SCF `/tmp` 固定 512MB，整段视频落盘撑爆 | 改为 ffmpeg 流式读 COS URL |
| 匿名用户调云函数 403 | **平台对匿名身份的硬限制**，CLI/MCP/策略/网关四条路都解不了 | 改「匿名登录 + HTTP 直连 Bearer + 后端解 JWT」 |
| 401 鉴权事故 | 前端后端**各跑一套不兼容的鉴权方案**，我构建前端时把线上覆盖了 | 后端只打最小补丁（改一个函数），其余字节不动 |

> **安全取舍（当时已告知）**：修复后的 `userIdFromBearer` **不验签**，理论上可伪造 JWT 冒充任意 uid。因为是个人测试工具、且产品当时完全不可用，按"可用优先"处理。**若上真实用户必须改为验签。**

### Gemini 全线尝试与证伪（9/10 - 9/11）

用户嫌千问弱，想换 Gemini。这条路走了两天，结论是**封死**：

- Google Cloud 对大陆 IP 段**主动发 RST**，TCP 握手都进不去
- 试过 CF Workers（`workers.dev` 被墙）、CF Pages（可达但 Functions 不执行）、EdgeOne Pages（拦境内请求）、Deno（注册 403）—— **全部失败**
- 最终用 **CF Pages 中继打通**，但同素材对照测试后**放弃**：

| 模型 | 同一段 33 秒素材的结果 |
|---|---|
| Gemini 3.6-flash | 总评「这段比赛的重点已整理好。」**空话，球员 0 人、事件 0 条** |
| 千问 qwen-vl-max | 3 名球员各自 3 条具体点评 + 亮点「**第 24 秒**中场精准直塞」+ 关键时刻「00:00:22 抢断」 |

**结论：「分析不出东西」的锅在模型，不在 prompt。**

### ★ 空结果根因实锤（9/12）

看板全空的真凶不是 prompt、不是素材、不是回填 —— **是阿里云百炼账号欠费**。

- `rounds[]` 里 6 轮全部 `success:false`，error 都是同一句：`Arrearage - Access denied`
- **但任务状态却写 `succeeded` / `error:null`** —— 模型一次都没跑起来，后端却报成功

由此暴露一个**真实产品缺陷**：0 轮成功时不该伪装成功。这条已写成需求文档。

### ★ 账单实锤：钱到底花在哪（9/12）

用户提供账单，查清了两条**完全独立**的账：

**COS 侧（钱的大头）**：9 月 4 笔扣费合计 **6.07 元**，全部是「COS 对象存储-上海」。
- 单价：**外网下行 0.5 元/GB**、存储 0.118 元/GB/月 → **取 1 次 ≈ 存 4.2 个月**
- 出血点：一场分析把同一视频拉了 5 次 ≈ **4.89 元/任务**

**CloudBase 侧（不是钱，是额度）**：免费体验版 3,000 点/月，9/12 已用 2,471 点 → 剩 871 点 / 12 天。

**关键结论**：云存储模块消耗 0.02 点、CDN 流量 0 Byte ⇒ **视频根本不走 CloudBase 通道** ⇒ 升级套餐（19.9 元/月）**一分钱都省不到 COS**。

### 假数据回路清除（9/12）

代码体检发现一条**生产可触达的假数据回路**：从历史记录点开无云端分析的老记录 → 触发 `engine.ts`（343 行伪随机）→ 生成一份"像真的"假报告。

处理：连带历史功能一起移除 7 个文件（含 4 个假数据/演示页），`storage.ts` 重写为内存单槽。**主包从 243.86 kB 降到 224.77 kB。**

## 阶段六 · 提示词翻案（9/13）—— 认知转折点

这是**产品逻辑发生质变的一天**。

### 转折：从「数次数」到「讲好坏」

原来 6 轮 prompt 里有两轮在让模型数「传球几次、射门几次」。

**但精确计数恰恰是 VLM 最大的弱项** —— 逼它数，它就只能编。

改成 3 轮定性描述后（团队亮点与不足 / 球员分析 / 动作矫正），质量立刻变好：

| 指标 | 6 轮（数次数） | 3 轮（讲好坏） |
|---|---|---|
| 39 秒视频 token | 325k | **150k（省 54%）** |
| 质量 | 编造、数字全空 | 用户评价「分析的很好」 |

**由此定论：提示词 > 模型。**

### 其他关键改动

- **后端分模式**：修掉「改一个模式的 prompt 会牵连全部三个」的缺陷 —— 按 `analysis_mode` 分支选 prompt 组。
- **评分体系补全**：发现报告页的评分位一直空着，因为 **prompt 里根本没这个维度**（原来的 `score` 指的是"比分"不是"评分"）。补上综合评分 + 五维分项（跑动/进攻/防守/对抗/传球）+ 每维文字分析 + 对手表现。
- **训练模式瘦身**：只保留入口（点进去显示「待开发」），业务代码删除。

### 关键发现

- **Token Plan 不能买**：百炼的 Token Plan（¥39/月）**明文禁止 API 调用**，只限交互式编程工具。而且它比按量付费还贵 —— `qwen3.8-flash` 输入 ¥0.8/百万，实测一次分析约 0.12 元。
- **免费额度按模型独立发放**（各 100 万 token），可轮换模型白嫖 —— 但这条路已经走完了。
- v1.1.0 / v1.2.0 相继发布。

## 阶段七 · 走向 15 分钟（9/14）

### 起因

用户发现报告页评分留空 → 引出「删除无关提示词」→ 进而提出**要扩到 15 分钟**。

### 关键发现：真正的瓶颈不是压缩

查证官方文档后确认了一条**比压缩更致命的限制**：

> 模型抽帧数**封顶 512 帧**。所以时长 ≥128 秒后，**每帧固定只有 483×272**——球衣号码基本认不出。

也就是说，15 分钟视频如果不动采样参数，**压得再清楚也没用，模型根本看不到**。

### 三连改

**① 时长与前端限制**
- 后端时长上限 5 分钟 → 15 分钟
- 前端硬门 5 分钟 → 15 分钟（不改则根本传不了）
- 同步 2 处 UI 文案为「推荐 2–15 分钟」

**② 压缩策略：从「固定码率」到「恒定像素密度」**
- 旧逻辑按「目标体积」反推码率 → 长视频会被压糊
- 新逻辑固定 0.1 bpp（像素密度），**体积超限时降分辨率而不是降画质密度**

**③ 采样：单帧分辨率按时长动态抬高**
- `total_pixels` 从固定 67M 改为 `max(67M, 帧数×262144)`，上限 134M
- 保证单帧 ≥ 683×384（号码可辨）
- **短视频仍走 67M 基线 → token 成本不变**

### 各时长验算结果

| 视频时长 | 抽帧 | 模型单帧 | 压缩后 | 体积 |
|---|---|---|---|---|
| 33 秒 | 132 | 951×535 | 1280 宽 | 11MB |
| 5 分钟 | 512 | 683×384 | 1080 宽 | 72MB |
| 15 分钟 | 512 | 683×384 | 640 宽 | 76MB |

### ★ 真实核验通过

用户实测 3 个视频：

| 视频 | 结果 |
|---|---|
| 4 分多钟 / 300MB ×2 | ✅ 分析很好 |
| 2 分多钟 / 700MB ×1 | ✅ 分析很好 |

**大体积 + 长时长的真实素材全部跑通，这一阶段的目标达成。**

## 附录 A · 14 条关键发现

1. **提示词 > 模型** —— 同样素材，改提示词的质量提升远大于换模型
2. **VLM 会编造**：精确计数、控球率、无记分牌比分、球员位置；可靠的是号码、文字评价、记分牌
3. **「分析不出东西」的锅常在模型不在 prompt** —— 千问 vs Gemini 同素材对照，Gemini 全是空话
4. **抽帧数有上限** —— 长视频单帧分辨率会被摊薄，这是比体积更致命的瓶颈
5. **`total_pixels` 是整段视频的总预算**，不是每帧 —— 降 fps 省不了 token
6. **画质瓶颈在码率不在分辨率** —— 压到 16MB 是灾难
7. **COS 的钱在「出」不在「存」** —— 取 1 次 ≈ 存 4.2 个月
8. **CloudBase 套餐省不到 COS 一分钱** —— 两条完全独立的账
9. **模型会下线** —— `qwen-vl-max/plus` 被阿里云下线，报告直接失效
10. **匿名用户调云函数被平台硬限制**，四条路都解不了
11. **Token Plan 禁止 API 调用**，且比按量付费更贵
12. **两条代码线混搭 = 隐性雷** —— 存储路径不一致导致永久卡 0%
13. **失败态不能伪装成功** —— 0 轮成功却报 `succeeded`，比失败更糟
14. **前端改完必须重新 build 再部署** —— 否则改动不生效

## 附录 C · 反复踩过的坑

1. `tcb fn deploy` **必须给函数名**，否则进交互菜单被 SIGKILL(137)
2. `tcb hosting deploy` **不能带 `yes ""`**（触发登录失败）
3. `cloudbaserc.json` 虽在 .gitignore 但被 force-add → `git reset --hard` 会清密钥
4. `haoqiu-api` 必须 `--dir .` 部署；**严禁本地构建部署**（仓库与线上曾分叉）
5. 前端改完**必须清 dist 重新 build**（`emptyOutDir:false` 会堆历史包）
6. 装依赖必须 **`env -u NODE_OPTIONS` + `npm ci`**
7. **`db/rc_task/` vs `db/task/`** 前缀必须两端对齐
8. **排查「看板全空」第一步永远是看 `text_result.rounds[].error`**
9. `/health` 的任务探测写死 `db/task/`，看不到 `db/rc_task/` 新任务（诊断盲区）
10. SCF `/tmp` 固定 512MB，**绝不整段落盘**
11. 云函数环境变量禁用 `SCF_` / `QCLOUD_` / `TENCENTCLOUD_` 前缀
12. 云函数**无 CLS 日志**，只能靠任务 JSON 排查
13. macOS BSD grep 不支持 `\|` 做「或」
14. **UI 位置由用户决定，先问再动；删除类操作先列清单；失败要如实说**
