# 好球Ai · 真实 AI 接入方案 v1

## 一、已拍板的方向（用户确认）
- **第一目标**：先出「AI 分析报告」（定性分析），不做精确统计。
- **路线**：通用视觉大模型 API（云端）。
- **预算**：用户可付费。

## 二、硬件结论（本地跑不了）
- 用户 Mac：Intel Core i5-8259U、8GB 内存、磁盘剩余约 5GB、无独立 GPU。
- 结论：本地跑 YOLO 等模型不可行（CPU 硬算太慢、磁盘装不下依赖），必须走云端 API。

## 三、选型（默认，可换）
- 首选：阿里云通义千问 VL（qwen-vl-max），视频理解成熟、国内可付费、有 dashscope SDK。
- 备选：腾讯云混元、智谱 GLM-4V、OpenAI GPT-4o（需海外支付）。
- 实现上做 provider 抽象，换模型只改配置。

## 四、架构
```
前端 Vite SPA
  │ 上传视频 + 球员名单
  ▼
后端 FastAPI（Python）
  │ 抽帧（opencv/ffmpeg）
  │ 分批调用 VLM API
  │ 汇总
  ▼
返回报告 JSON → 前端渲染
```

## 五、第一版能做什么（真实分析，非模拟）
- 上传视频 + 球员名单 → 后端抽帧 → VLM 理解 → 生成：
  - 比赛整体总结
  - 关键事件（射门/进球/突破等）+ 时间点
  - 高光片段描述
  - 整体/个人表现点评（粗粒度；归因到具体球员受限）
- 明确限制：细粒度「拿球成功 N 次」精确统计做不到（用户已接受，后续阶段再做）。

## 六、分阶段
1. **阶段1**：后端骨架 + 抽帧 + VLM 调用封装 + mock 模式（无 key 也能跑通接口）。
2. **阶段2**：前端接后端，替换本地模拟引擎。
3. **阶段3**：用户提供 API key，真实联调。
4. **阶段4**：迭代精度（号码识别 / 队色分组做球员归因）。

## 七、需要用户提供
- 云 API key（阿里云 DashScope，开通通义千问 VL 后获取）。
