# 好球Ai · MVP 阶段一 · 看板改版需求（V1.1）

> 变更来源：用户验收阶段提出的方向调整。本需求取代 V1.0 中「两队 + 五维评分 + 分层个人报告」的设计。

## 一、变更目标

从「两队对抗 + 五维能力评分 + 球员个人子页面」改为：

**单队 + 客观数据看板 + 1-10 综合评分**，数据全部平铺在第一页看板，不设下一层级。

核心理念：只统计视频里**客观可见**的数据（拿球、失误、传球、射门…），不做五维定性评分。

## 二、数据模型改动

### Match
- 删除 `redTeam` / `blueTeam` 对手信息，改为单个 `teamName`（我的队名）。
- 其余（name/date/type/duration/videoName/createdAt）不变。

### Player
- 删除 `team` 字段（单队，无需区分）。
- 保留 `id / name / number`，`position` 可选。

### PlayerAnalysis（重定义）
- **删除** `dimensions`（五维能力）与 `strengths / problems / suggestions`（定性教练文案）。
- 新增 `stats` 客观数据对象：
  ```
  stats: {
    touches: number          // 拿球次数（接球/触球总次数）
    touchesSuccess: number   // 拿球成功次数
    turnovers: number        // 失误次数（丢球、停球/处理失误）
    passes: number           // 传球次数
    passesSuccess: number    // 传球成功次数
    shots: number            // 射门次数
    shotsOnTarget: number    // 射正次数
    dribbles: number         // 突破成功次数
    interceptions: number    // 拦截次数
    tackles: number          // 抢断次数
  }
  ```
- `score` 改为 **1–10 综合分**（保留 1 位小数），**由 stats 客观推导**，不能凭空打分。

## 三、评分规则（1-10，有据可依）

- 基准 6 分，正向贡献加分、失误扣分：
  - 加分：拿球成功、传球成功、射正、突破、拦截、抢断
  - 扣分：失误
- 最终 `clamp` 到 [3, 10]，保留 1 位小数。
- 权重由开发自定，但必须保证「数据好 → 分高」，逻辑可解释。

## 四、页面改动

1. **MatchNew（创建比赛）**：三步向导改为
   - 比赛信息（名称 / 日期 / 类型 / **我的队名**）
   - 上传视频（同现有逻辑，可跳过用示例）
   - 我的球员名单（号码 + 姓名，一键示例名单）
   - 删除对手队录入。

2. **MatchReport（改名为「比赛看板」，第一页核心）**：
   - 顶部：队名 + 比赛时长 + 全队数据总览（总拿球 / 总传球 / 总射门 / 总失误）
   - 球员数据表（平铺）：每位球员一行/一张卡，展示姓名、号码、**综合分（1-10）**、拿球成功、失误、传球(成功/总)、射门(正/总)、突破、拦截、抢断
   - 精彩片段列表（保留）
   - 保留「演示数据」标识。

3. **删除 PlayerReport 页面**及路由 `/match/:id/player/:pid`。

4. **Analyzing**：阶段可简化为「上传 → 识别球员 → 统计事件 → 生成看板」。

## 五、视觉

保留绿茵场风格，但**不再红蓝两队**，改为单一主题色（绿色系）。

## 六、验收标准

- 单队流程跑通：创建（只填自己队）→ 名单 → 分析 → 看板
- 看板平铺所有球员的客观数据 + 1-10 评分
- 无五维、无对手队、无个人子页面
- `npm run build` 通过
