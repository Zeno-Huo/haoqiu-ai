## 任务 1（必须）：恢复 queued 任务的两处补发触发

### 问题

回填版 `src/service.ts` 里 **dispatch 调用数为 0**，只有 `index.ts` 两处（recover 路由、创建成功后）。
线上 `dist/src/service.js` 有 **3 处**触发，其中两处是**任务卡死的唯一自救通道**，被漏掉了：

**① `taskForUser` 轮询补发（线上 service.js L99-110，最关键）**

```js
// 轮询路径补触发：任务建好后一直停在 queued，说明它从未被真正调度过（历史 bug 导致
// 触发缺失）。这里补发一次，避免前端永远停在「排队 / 锁定球员」。
// haoqiu-vlm 的 claim 有 CAS 保护，任务被领走后状态转为 leased，不会重复分析。
if (task.mode === "instant" && task._id.startsWith("rc_") && task.status === "queued") {
    const ageMs = this.now().getTime() - new Date(task.created_at).getTime();
    if (ageMs > 60_000) {
        try { await dispatchAnalysis(task._id); }
        catch { /* 维持原状返回，下次轮询再试 */ }
    }
}
```

**② `createInstantJob` 的 existing 分支补发（线上 service.js L135-147）**

```js
if (existing) {
    // 任务已存在却仍停在 queued，说明它被创建后没有真正触发过分析（触发缺失/失败）。
    // 补发一次，否则前端会一直停在「排队 / 锁定球员」。
    if (existing.status === "queued") {
        const ageMs = this.now().getTime() - new Date(existing.created_at).getTime();
        if (ageMs > 60_000) {
            try { await dispatchAnalysis(existing._id); }
            catch { /* 补发失败先不打断查询，下次轮询会再试 */ }
        }
    }
    return { task: existing, created: false };
}
```

### 为什么必须补

回填版入口在触发失败时返回 **202 + `DISPATCH_PENDING` 警告**（这一点与线上一致，是对的），
于是调用方**不会重试创建**，只能轮询。而轮询路径不再补发 → **触发一旦失败，任务不会自愈**。

实测确认：`/worker/v1/instant/recover` 在全仓库中**没有任何自动调用方**（无定时触发器、无代码调用），
所以它不是恢复手段。

后果：任务停在 `queued` 直到 `queuedTtlSeconds`（默认 1800 秒）被判 `STALE_QUEUED` 失败。
这正是历史事故「卡 0% / 永远排队」的表现——当时就是靠这两处补发修好的。

### 要求

- 触发写入 `src/service.ts` 的 `taskForUser` 与 `createInstantJob`（existing 分支），逻辑照抄上面两段。
- **保留** main 已有的 `expireTaskIfStale` TTL 判定（两者不冲突：先补发，TTL 作为 30 分钟兜底）。
- **保留** 入口层单次触发与 202 降级（不要改回「服务层也触发」）。
- 两处补发都必须是 `try/catch` 静默失败，绝不能把查询接口打成 5xx。

## 任务 2（必须）：恢复两条 legacy 护栏

线上 `taskForUser` 开头还有两条护栏（回填后丢失，现有实现直接等于 main 的旧版）：

```js
if (task.mode === "instant" && (task.text_result?.model === "demo" || task.text_result?.content?.includes("演示数据")))
    return { ...task, status: "failed", stage: "failed", text_result: undefined,
             error: { code: "LEGACY_DEMO_RESULT", message: "历史演示结果不可作为真实报告，请重新分析" } };
if (task.mode === "instant" && !task._id.startsWith("rc_") && !["succeeded", "failed"].includes(task.status))
    return { ...task, status: "failed", stage: "failed",
             error: { code: "LEGACY_TASK_REANALYSIS_REQUIRED", message: "旧任务无法安全恢复，请创建新的分析任务" } };
```

第一条是**防伪数据护栏**：没有它，历史演示数据（`model === "demo"` 或内容含「演示数据」）会被当成真实报告展示。
这是本项目最不能出的问题，必须补回。第二条把预 `rc_` 时代的未完成任务显式判失败，避免前端永远轮询。

要求：插在 `taskForUser` 取到 `task` 之后、返回之前（在补发判定之前）。
