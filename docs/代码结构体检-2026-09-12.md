## 1. 必须处理：假数据回路（生产环境真的能点到）

这条最要紧，因为它直接踩"不要假数据"的红线。

链路是这样的：

```
lib/matchLink.ts  matchTarget()
  ├─ analysisMode === 'single'   → /match/:id/tracking
  ├─ analysisMode === 'training' → /match/:id/training
  └─ 其它                        → /match/:id/analyzing   ← 落这里
                                      ↓ 用户点一下
pages/Analyzing.tsx:16   saveAnalysis(id, analyzeMatch(currentMatch)); navigate(`/match/${id}`)
pages/MatchReport.tsx:2  import { buildMatchSummary } from '../lib/engine'
```

- `lib/engine.ts`（**343 行**）文件头自己写着「本地模拟 AI 分析引擎 / 生成「真实感、确定性」的客观数据」——**它不调任何模型，纯伪随机**。
- `lib/seed.ts`（46 行）是它的确定性随机种子，让同一场比赛每次"算"出来的假数据都一样，所以看起来特别像真的。
- 从 History 点开一条**没有云端分析结果**的历史记录 → 进 `/analyzing` → 点按钮 → 得到一份伪随机生成的"报告"。

也就是说，产品已经在 VLM 上了，但**旧的模拟引擎还挂在生产路由里没摘**。建议：把 `Analyzing.tsx` / `MatchReport.tsx` / `engine.ts` / `seed.ts` 一起退役，`matchTarget()` 的无分析分支改成引导用户去重新分析（走 VLM），而不是本地编一份。

（顺带：`lib/analysisMode.ts` 里有 `'practical' | 'demo'` 两种模式，也请确认 `'demo'` 是否还有意义。）

- `cloudbase-backend/` 的本地源码停在 **8/30**；线上跑的是回填版（Codex `133cf15`，9/12 21:10 部署）。
