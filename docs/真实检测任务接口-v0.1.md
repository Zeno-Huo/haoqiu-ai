# 好球Ai 真实检测任务接口 v0.1

状态：开发基线  
目标：把现有网页与腾讯云 HAI 上已经跑通的第一个足球检测模型连成最小真实闭环。

## 1. 能力边界

本接口只承诺：

- 接收一段比赛视频；
- 异步运行现有球员检测模型；
- 返回任务状态、处理进度、模型版本和警告；
- 生成带检测框的结果视频；
- 返回逐帧检测的基础诊断信息。

本接口暂不承诺：

- 唯一球员人数或球员身份；
- 真实比分、控球率、传球、抢断、助攻、失误；
- 球员持续跟踪、球衣号码、球队归属；
- 战术、位置、换人或阵容建议。

逐帧检测次数不得在前端展示为“人数”或“事件次数”。

## 2. 服务约束

- 服务框架：FastAPI；
- GPU：单个 Tesla T4；
- 同一时间只运行一个 GPU 任务，其余任务排队；
- 复用现有 Python 环境、模型权重和检测脚本，不安装其他足球模型；
- v0.1 先在 HAI 本机 `127.0.0.1:8000` 验证；
- 未经确认不得修改腾讯云安全组、开放公网端口或关闭实例；
- 不在前端代码中保存 SSH 密码、云密钥或长期 API Token。

## 3. 创建任务

`POST /api/v1/detection-jobs`

请求类型：`multipart/form-data`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `video` | File | 是 | MP4/MOV；v0.1 上限 300MB、15分钟 |
| `client_match_id` | string | 否 | 网页本地比赛 ID，仅用于关联 |

成功响应：HTTP `202`

```json
{
  "job_id": "job_01...",
  "client_match_id": "m_01...",
  "status": "queued",
  "progress": 0,
  "created_at": "2026-08-24T12:00:00Z"
}
```

## 4. 查询任务

`GET /api/v1/detection-jobs/{job_id}`

处理中：

```json
{
  "job_id": "job_01...",
  "client_match_id": "m_01...",
  "status": "running",
  "progress": 42,
  "eta_seconds": 18,
  "stage": "detecting",
  "created_at": "2026-08-24T12:00:00Z",
  "started_at": "2026-08-24T12:00:02Z"
}
```

成功：

```json
{
  "job_id": "job_01...",
  "client_match_id": "m_01...",
  "status": "succeeded",
  "progress": 100,
  "stage": "completed",
  "model": {
    "name": "football-player-detection",
    "version": "current-hai-weight"
  },
  "input": {
    "filename": "match.mp4",
    "duration_seconds": 20.3,
    "width": 720,
    "height": 1280,
    "fps": 30
  },
  "diagnostics": {
    "processed_frames": 608,
    "source_frames": 608,
    "full_video_processed": true,
    "classes_seen": ["player", "goalkeeper", "referee"],
    "frame_detections_by_class": {
      "player": 512,
      "goalkeeper": 8,
      "referee": 24,
      "ball": 3
    }
  },
  "warnings": [
    "检测结果可能包含漏检和类别误判",
    "逐帧检测次数不代表唯一球员人数",
    "检测视频逐帧处理完整源视频，暂不保留原视频音轨"
  ],
  "artifacts": {
    "annotated_video_url": "/api/v1/detection-jobs/job_01.../artifacts/annotated-video"
  },
  "completed_at": "2026-08-24T12:00:40Z"
}
```

失败：

```json
{
  "job_id": "job_01...",
  "status": "failed",
  "progress": 0,
  "stage": "failed",
  "error": {
    "code": "VIDEO_DECODE_FAILED",
    "message": "无法读取该视频，请更换文件后重试"
  }
}
```

状态枚举：`queued | running | succeeded | failed`。

阶段枚举：`queued | probing | detecting | rendering | completed | failed`。

`eta_seconds` 仅为当前逐帧处理速度推算的剩余秒数；排队、探测和失败阶段可为 `null`，不得作为完成时间承诺。`full_video_processed=true` 表示源视频帧已完整进入检测流程，不代表所有球员均被正确检出。本版本不抽帧、不做智能剪辑。

## 5. 下载检测视频

`GET /api/v1/detection-jobs/{job_id}/artifacts/annotated-video`

- 成功返回 `video/mp4`；
- 任务未完成返回 HTTP `409`；
- 任务不存在返回 HTTP `404`。

## 6. 健康检查

`GET /health`

```json
{
  "status": "ok",
  "gpu_available": true,
  "model_loaded": true,
  "active_jobs": 0,
  "queued_jobs": 0
}
```

## 7. 前端展示规则

真实检测区只能使用以下表述：

- “真实检测任务”；
- “正在检测画面中的球员候选”；
- “查看检测视频”；
- “可能存在漏检和类别误判”。

禁止使用：

- “AI 已识别全部球员”；
- “真实控球率/传球/抢断”；
- “共识别到 N 名球员”（除非后续加入稳定跟踪和去重）；
- 把 `frame_detections_by_class` 转换成球员人数或事件次数。

现有球队复盘 Demo 与真实检测区必须分开显示，Demo 数据继续明确标注为演示数据。

## 8. v0.1 验收用例

1. `GET /health` 返回模型与 GPU 可用；
2. 上传现有 20 秒测试视频，接口在 2 秒内返回 `202 + job_id`；
3. 任务经历 `queued/running` 后到达 `succeeded` 或给出可读失败原因；
4. 成功任务能下载并播放带检测框的 MP4；
5. 网页刷新后可用 `job_id` 恢复查询；
6. 网页不把逐帧检测统计包装为真实球队或球员数据；
7. 未配置真实服务时，既有本地 Demo 仍可独立使用。
